# 開發紀錄 · Development Log

> 本檔記錄燼語墓園從一支參考影片到上線、再到補齊驗證的完整過程：每一步的需求、做法、決定與決定者、出過的問題與修法。用途是之後整理成網路課程與教學說明。
> English summary: a chronological record of how this project was built with an AI coding assistant — every request, decision, bug (symptom → root cause → fix → regression guard) and the verification loop. Kept as raw material for a future course.
>
> 維護規則：每次改動在 §4 時間軸加一列；修 bug 時在 §5 加一列，並寫明「哪個測試防止再犯」。

## 1. 專案一句話

把一支示範影片裡的「AI 做 3D 法術特效」方法拆解清楚，做成瀏覽器打開就能玩的單檔 WebGL 遊戲，再一路長成有故事、有測試、有雲端自動驗收的公開作品。

## 2. 工作方式

| 角色 | 做什麼 |
|---|---|
| 作者 | 提需求、拍板每個決策（公開或私有、輕重規模、劇情前提、階段順序）、授權每一次推送 |
| AI 助手（Claude Code） | 解析影片、寫程式、跑測試、畫圖、寫文件；每個需要決定的地方先列選項與推薦答案，等作者拍板 |

固定規則：推送到 GitHub 前一定先問；付費的 AI 生成服務先報價；公開前掃一次隱私（本機路徑、email、工作場所名稱）；每階段只加一項玩法。

## 3. 方法來源

- 參考影片：https://www.youtube.com/watch?v=waaAXPt7RG8
- 取得內容：用 yt-dlp 下載影片的自動字幕（不下載影片本體），把字幕整理成純文字後拆解。
- 拆解結果（完整版見 [METHOD.md](METHOD.md)）：整段影片不能直接當法術；每招拆成「翻頁圖＋程式粒子與燈光＋3D 模型」；火球是多片永遠面向鏡頭的方塊疊出來的；三條貼圖路線（AI 影片、一次畫 16 格、程式即時算）的畫質與成本對照。

## 5. 問題與修正紀錄

| # | 症狀 | 怎麼發現 | 根因 | 修法 | 防止再犯 |
|---|---|---|---|---|---|
| 1 | 本機開檔中文全是亂碼，死亡畫面一開始就蓋住遊戲 | 第一張瀏覽器截圖 | 檔案沒有宣告 UTF-8；`.overlay{display:flex}` 蓋過 HTML 的 `hidden` 屬性 | 加 `<meta charset>` 與 `[hidden]{display:none!important}` | 端對端「死亡畫面只在死亡時出現」 |
| 2 | 內建預覽面板截圖一直是舊畫面 | 截圖內容與遊戲狀態對不上 | 面板隱藏時瀏覽器暫停動畫迴圈 | 改用無頭 Chrome 透過 DevTools 協定擷取畫面 | 所有測試都走無頭 Chrome |
| 3 | 截圖時特效已經跑完 | 三路線對照圖的火球消失 | 等待截圖的 0.6 秒內，頁面自己的迴圈繼續跑 | 截圖前凍結頁面迴圈，只用手動逐格推進 | 截圖腳本固定做法 |
| 4 | 狀態列「擊倒」的數字掉到下一行 | 上線前的截圖 | 檔案沒有 `<!doctype html>`，瀏覽器進相容模式，id 選擇器不分大小寫，`#skills` 的樣式套到了 `#sKills` | 補 doctype、id 改名 | 其他驗證「doctype 存在」「id 不分大小寫也不重複」；突變測試會刪掉 doctype 確認變紅 |
| 5 | 探針施法全部沒有傷害 | 探針紅燈 | 探針把遊戲設成暫停，而施法只在遊戲進行中才接受 | 探針改成不暫停，整段同步執行 | — （測試本身的錯） |
| 6 | 探針只有第一招有傷害 | 探針紅燈 | 其他怪物把玩家咬死了，後面三招無法施放 | 探針凍結所有怪物、每招前補滿血 | — （測試本身的錯） |
| 7 | 架構圖節點標籤多了引號、同一欄的連線亂繞、只能放一張流程圖 | 擷取架構圖畫面 | 圖檢視器的解析器不去引號；連線一律左右相接；只渲染一張流程圖 | 標籤不加引號；同欄改上下相接、往回連線從右側繞；流程圖分頁可放多張 | 其他驗證「每份 .mmd 都原樣內嵌在檢視器裡」＋mermaid 語法檢查 |
| 8 | 架構圖檢視器裡留著內部文件名稱 | 公開前掃描 | 圖檢視器範本的說明文字沿用自內部範本 | 改成中性說法 | 推送前隱私掃描（本機路徑、email、工作場所名稱） |
| 9 | 翻頁圖每格最外圈像素不是全透明 | 單元測試第一次跑 | 邊緣淡出的範圍到格子邊才歸零，第 1 圈像素還有 6% 不透明，線性取樣會滲到隔壁格 | 淡出提早在離邊 4 像素處歸零（程式畫圖與即時算兩邊都改） | 單元「每格邊緣全透明」；突變測試會改回舊值確認變紅 |
| 10 | 載入頁面時主控台出現 404 | 單元測試的「無錯誤」檢查 | 瀏覽器自動要網站圖示，而網站沒有 | 宣告空白圖示 | 每組測試都檢查主控台 0 錯誤 |
| 11 | 施法動作還沒結束時按下未學會的技能，沒有任何提示 | 端對端第一次跑 | 判斷順序先檢查「正在施法」就直接返回，輪不到「還沒學會」的提示 | 先判斷是否解鎖，再判斷施法與冷卻 | 端對端「施法中按 2 也會出提示」；單元「未解鎖技能不能施放」；突變測試會拿掉解鎖判斷確認變紅 |
| 12 | 驗收工具偶爾說「首領黑暗階段沒觸發」 | 一鍵全跑時偶發紅燈 | 探針用會爆擊的傷害函式把首領打到四成血，12% 機率爆擊直接打死，黑暗階段來不及觸發 | 探針直接設定首領血量 | 規則：測試裡不用有亂數的函式推進狀態；連跑三次確認穩定 |
| 13 | 雲端自動測試：端對端「施法中按 2 出提示」失敗，本機卻通過 | GitHub Actions 第一次雲端跑 | 測試讀的是提示框經過 0.3 秒淡入動畫後的透明度，雲端機器較慢，讀到淡入到一半的值 | 改讀遊戲直接設定的透明度目標值，並等待最多 2 秒 | 規則：測試不讀動畫中的計算值 |
| 14 | 端對端「法術在真實時間內打死怪物」偶發失敗 | 補開發紀錄後一鍵全跑 | 自由試玩的怪物隨機分布，被凍結後不一定站在法術落點上 | 測試先把 9 隻怪擺到游標瞄準的位置 | 連跑三次全綠；規則同 #12：測試不依賴隨機生成的位置 |

## 6. 每次改動的標準流程

```text
改程式或內容
  → 本機 npm test（煙霧、閘門自測、單元、端對端、其他驗證、突變測試）
  → 有紅燈：修功能本身，不准為了過而放寬測試，重跑
  → 全綠：在本檔 §4 加一列；修 bug 時在 §5 加一列
  → 問作者要不要推送
  → 推送後 GitHub Actions 在雲端重跑全部
  → GitHub Pages 部署
  → npm run test:live 對線上網址再跑一次
  → 綠了才算上線
```

圖示版見 [architecture.html](diagrams/2026-11-15_EmberGraveyard/architecture.html) 的「✅ 驗證流程」分頁。
